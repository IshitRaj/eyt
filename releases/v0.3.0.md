# EYT v0.3.0 - Experimental

This prerelease contains research-informed engineering guidance for coding agents. Its real-world effectiveness has yet to be established through controlled evaluation.

## Changes developers will see

- Requests to revise a feature now start with what the revision replaces and what must still work. The skill asks agents to check both through the feature's normal entry points.
- The verification guide asks whether a new regression test fails on the original bug for the expected reason. The security guide pairs scoped tool access with a check that legitimate work still succeeds.
- The UI guide uses the decision a user needs to make to choose hierarchy, grouping and controls. It gives examples for long content, supported themes, dialog focus, failed saves and reloads.
- The core is shorter, with nine task-specific references. To upgrade, copy the full skill directory as described in the [installation guide](https://github.com/IshitRaj/eyt/blob/v0.3.0/README.md#install-the-single-skill). Existing installations use the same name and invocation.

## Evidence and next experiment

FeatureLoop motivates testing retained requirements. CodeAssay motivates checking the grader against both valid implementations and deliberate faults. AgentScript-Eval motivates recording which instructions the agent actually saw. Design examples from Kole Jain are paired with WCAG, WAI-ARIA and USWDS guidance. The [source review](https://github.com/IshitRaj/eyt/blob/v0.3.0/docs/RESEARCH.md) documents their methods, scope and limitations.

The previous project evidence consists of one informal v0.1.0 comparison. The next experiment should run the same agent on a save flow and a subsequent requirement change, with and without EYT. Compare retained behavior, missed faults, safety failures and token/runtime cost using the [paired evaluation protocol](https://github.com/IshitRaj/eyt/blob/v0.3.0/evaluations/RUBRIC.md). Report unsuccessful runs alongside successes.
