# Research informing v0.3.0

Reviewed for the November 2026 experimental release. EYT v0.2.0 already covered authorization, write recovery and real browser journeys. The gaps were how to preserve behavior across revisions, tell whether a test could catch a fault, and separate instruction exposure from task performance. The studies below inform those decisions. None evaluated EYT.

## Engineering and agent behavior

- **FeatureLoop.** Twelve models implemented staged requests in persistent workspaces across 61 tasks from 34 repositories. Of 733 failed stages receiving corrective feedback, 113 passed all current checks within two revisions. EYT can ask agents to exercise changed behavior through the normal entry point and rerun earlier obligations that still apply. These are bounded repair attempts on scripted trajectories. [Paper, §§2–5](https://arxiv.org/html/2610.35488v2)
- **CATTest.** Browser agents used Playwright to investigate 102 generated web apps with annotated defects. The highest fine-grained R-score was 42.57 out of 100. An agent could flag a faulty app while missing the particular broken interaction. Exercise a representative journey and compare the observed result with a specified expectation. For evaluations, count independently confirmed defects and false reports. Annotations can miss genuine defects, and the study excludes accessibility and aesthetic judgments. [Paper, Table 1 and Limitations](https://aclanthology.org/2026.emnlp-main.2075.pdf)
- **HarnessSecurity-Bench.** Across selected comparisons in a 23-task, six-harness study with one fixed model, enabling automatic approval increased utility from 77.1% to 95.4% and unauthorized effects from 29.2% to 95.6%. Broad read-only controls also obstructed legitimate work. Preserve host-enforced permissions, limit sensitive operations to the scope authorized, and score allowed outcomes and unauthorized side effects separately. The intervention changed runtime controls. The study did not test prose instructions as an enforcement mechanism. [Paper, auto-approval results](https://arxiv.org/html/2610.07639v2)
- **TaoD2C-Bench.** The authors annotated 2,861 commercial designs and evaluated eight models on design-to-code tasks. Supplying expert requirements improved mean scores for five code dimensions by 6.82–24.24 F1 points while visual scores changed little. Record required components, grouping and layout relationships when the project specifies them, and accept alternative implementations that satisfy those constraints. The benchmark measures conformance to a target component library and expert annotations. It does not establish aesthetic preferences or end-user usability. [Paper, Tables 2–3](https://arxiv.org/html/2610.10374v1)
- **AgentScript-Eval** graded 100 Salesforce DSL tasks through compilation and behavioral checks. In Table 1, the same Opus agent passed all checks on 33% without skills, 28% with documentation, 14% with the live pack and 37% after one skill was rewritten. Crucially, the documentation had three skills and the live plugin had 40 plus tools, so their comparison confounds delivery with catalog breadth (Appendix F). This single DSL motivates checking instruction uptake and experimentally separating wording, delivery and execution feedback. It establishes no generally superior delivery method. [Khati et al., Table 1 and Appendix F](https://arxiv.org/html/2611.13183v1)
- **Testing with Coding Agents** compared 114,134 merged PRs across 391 Java repositories. Within projects and controlling for change size, agent-supported PRs more often added tests. In the 95 buildable repositories the authors detected no difference in coverage of changed production code. Attribution was inferred and observational. Fault detection was not measured. EYT can evaluate that outcome directly with seeded behavioral faults. [Milanese et al.](https://arxiv.org/pdf/2610.35297)
- **CodeAssay** separated public feedback and hidden grading for 185 Python tasks. Auditing the ground truth changed 170 of 1,890 previously assigned correctness labels on fixed outputs. The hidden suite detected 2,999 of 4,008 reference mutants. A security-focused prompt did not consistently improve the selected static findings, which are proxies for security. Audit the grader against correct variants and known faults, and exercise relevant controls directly. This was stand-alone code generation, not repository-level EYT evaluation. [Siddeeq et al., sections 3 and 4](https://arxiv.org/html/2608.03535v2)
- **When Instruction Files Go Stale.** Across three stale instructions, the authors detected extra tool calls for one model following an obsolete test command. They did not detect the same difference in the other cases. Record effort alongside task outcomes. [Mehtiyev et al.](https://arxiv.org/abs/2611.09802)

## UI design sources

- In *Every UI/UX Concept Explained in Under 10 Minutes*, Kole Jain demonstrates how position and type distinguish an item's identity from its metadata, proximity groups related content, and state changes communicate that a control responded. His dark-mode example revisits foregrounds and surfaces together. EYT adapts these ideas into checks using real content and supported themes. [Video](https://www.youtube.com/watch?v=EcbgbKtOELY) and [caption text](https://prepublish.ai/youtube-transcript/EcbgbKtOELY)
- *7 UI/UX mistakes that SCREAM you're a beginner* follows a recipe app through inconsistent components, redundant elements and delayed feedback. *5 SaaS UI/UX mistakes that SCREAM you Vibe Code* shows a billing view where recurring cost deserves more emphasis and a decorative card can go. EYT asks what decision a screen supports. These practitioner examples offer no controlled usability comparison. The review used published descriptions and third-party mirrors of YouTube's automatic English captions. On-screen demonstrations were not independently inspected. [Beginner mistakes](https://www.youtube.com/watch?v=AH_ugxmLeUM), [captions](https://prepublish.ai/youtube-transcript/AH_ugxmLeUM), [SaaS redesign](https://www.youtube.com/watch?v=PDcQJOPby1k) and [captions](https://prepublish.ai/youtube-transcript/PDcQJOPby1k)
- USWDS distinguishes browsable collections from tabular comparisons and sequential content. WCAG 2.2 provides criteria for color, contrast, reflow, keyboard access, focus and status messages. The WAI-ARIA Authoring Practices Guide describes keyboard behavior for modal dialogs, including exceptions to returning focus to the opener. EYT uses these for specific checks. A short smoke test cannot establish conformance. Font counts, fixed spacing formulas and blanket bans on cards or gradients have no place in these checks. [USWDS cards](https://designsystem.digital.gov/components/card/), [WCAG 2.2](https://www.w3.org/TR/WCAG22/) and [APG modal dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

## Decisions to test

Keep detailed examples in task-specific references and measure actual reads and token use. Test whether checking retained requirements prevents regressions and whether agent-written assertions catch a seeded fault. Adding tests, loading more text, and matching a screenshot each describe an activity. Their value depends on the behavior independently observed. See the [comparison protocol](../evaluations/RUBRIC.md).
